The workshop becomes a package

jamai-core is the set of tools JamAI uses to listen to what Jerry plays, turn it into a score and a sound, and publish it. On 16 November 2026 it was made installable by someone who has never seen the house it grew in. This page shows what was built that evening and how the parts connect.

The path of a melody

Steps 1 to 4 existed before, spread over two repositories. Steps 5 to 7 are new.

  1. WriteABC notation: a text file with the title, key, meter and the notes.
  2. Renderabc2midi makes the MIDI, FluidSynth plays it through a soundfont, LAME writes the MP3.
  3. Engraveabcm2ps draws the score as SVG.
  4. PublishThe files go to your melody folder. The page that lists them is rebuilt.
  5. AnnounceOne fact is written to a ledger: a new melody, or a revised one.
  6. DeliverThe hub sends that fact once to each subscriber, signed.
  7. ReceiveA subscriber's webhook gets the title and the links to the MP3, MIDI and score.

One command, and it asks

Every value the tools need is declared once, in a file named settings, with what it is for and its default. The installer reads that file, so nothing is asked that is not declared and nothing is declared twice.

Render chain: whole. You can render and publish a melody.

1 · Ask

Fourteen questions, each with its purpose and a value in brackets. Enter keeps it.

2 · Write

Answers go to one plain file. The single secret is generated and kept apart, readable only by you.

3 · Link

Commands are linked by name. A file already there is renamed and kept, never deleted.

4 · Check

jamai doctor names each missing program, the package that brings it, and what stops without it.

A value is looked for in three places, in this order: your shell's environment, your settings file, the declared default. jamai config show prints each value with the place it came from.

Three ways a publication can go

The same melody is often published several times in a few minutes while it is being corrected. Subscribers should hear about the music, not about each correction. The publisher compares the new MIDI file with the one already published.

What changedFact announcedWhat a subscriber receives
The melody is newmelody.publishedOne delivery
The notes or the instruments changedmelody.revisedOne delivery, naming the version it replaces
Only the engraving changed, the MIDI is identicalnoneNothing

The rule comes from a real case: one piece was published three times in fifteen minutes on 16 November, and the second publication changed nothing that could be heard.

The hub

What a subscriber gets

  • An id and a secret, shown once
  • Each fact once, as a signed POST
  • Five more tries over about nine hours if their side was down
  • A test delivery on request

What the hub refuses unless told otherwise

  • Subscribing without an invite code
  • A webhook that is not https
  • A webhook that leads into a private network
  • Following a redirect

What a fact never carries

  • The ABC source of the melody
  • The session note, unless the owner allowed it
  • Anything about the house that published it

An invite code opens one subscription, expires after seven days, and is kept as a hash, so the file that stores invitations holds nothing a person could reuse.

How it was made that evening

asked

Fourteen sessions

Each running session that had touched music, publishing or packaging received one question: what do you know about JamAI, and what would a stranger need? Ten answered in writing. Four were cut off by a usage limit and have not been asked again.

read

The record of one piece

An earlier session had written down every command, version and decision behind op-021 Sens partagé. That inventory is where the list of programs and the "same MIDI, no announcement" rule come from.

caught

A defect, by the self-test

The first run failed 3 checks of 68. The hub compared two timestamps that only count seconds, so a fact from just before a subscription was delivered. The hub now counts by position in the ledger. The run after the fix passed 69 of 69, with one check added for that case. The same 69 then passed in a clean Ubuntu container.

aligned

With the access survey

A separate survey of the site proposed one sign-in for everything, with one-use invitations stored as hashes. The hub's invite codes follow that rule, and the hub keeps no list of people of its own.
